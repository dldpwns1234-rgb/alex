# 개발 로드맵 — 서리 변경 (Frostmarch)

**타겟: 안드로이드 폰, 세로 고정, 모바일 전용** (GDD D12)

---

## 원칙

> **"전부 얇게"가 아니라 "고리 하나씩 닫기".**

각 마일스톤이 끝날 때마다 **폰에서 플레이 가능하고, 실패할 수 있는 상태**여야 한다.
"실패할 수 있다"가 핵심이다. 실패 조건이 없는 빌드는 게임이 아니라 장난감이다.

**아트는 M5까지 미룬다.** 그 전까지 모든 것은 색깔 사각형과 기본 UI다.

## ⚠️ 타일맵 폐기(D13)가 로드맵에 미친 영향

| | 이전 (타일맵) | 현재 (슬롯 + 건물 화면) |
|---|---|---|
| 최대 난관 | **M2 가구 AI·물류** (3~4주) | 삭제됨 |
| 전투 | 자유 이동 + 길찾기 (3~4주) | 3열 고정 (2~3주) |
| 아트 부담 | 타일셋 + 스프라이트 (2주) | **화면 10종 + 파노라마 (3~4주)** |

**코드 난이도는 크게 내려갔고, 부담이 UI/아트로 옮겨갔다.**
총 기간은 비슷하지만 **위험의 성격이 바뀌었다** — "돌아가게 만들기"가 아니라 "10개 화면을 지치지 않고 그려내기"가 문제다.

### M0에서 실제로 부딪힌 것들

문서에 남기는 이유는 M1 이후 같은 함정을 다시 밟지 않기 위해서다.

| 문제 | 원인 | 해결 |
|---|---|---|
| 한글이 전부 빈 네모 | Godot 기본 폰트에 한글 글리프가 없다 | Noto Sans KR 번들 (5.9MB). **M5에서 한글 픽셀 폰트로 교체** |
| Android 익스포트 실패 | ETC2/ASTC 압축이 필수 | `textures/vram_compression/import_etc2_astc=true` |
| 임포트 오염 | Godot이 `build/` 산출물을 프로젝트 자산으로 스캔 | 익스포트 전에 `build/.gdignore` 생성 |
| 신호 카운터가 0 | **GDScript 람다는 값으로 캡처한다** | 테스트에서 배열(참조 타입)로 수집 |

**GUT 대신 자체 테스트 러너를 쓴다.** 소스 파일 다섯 개짜리 프로젝트에 애드온 수백 개
파일을 커밋하는 것은 균형이 맞지 않는다. 테스트가 실제로 늘어나는 M2에서 GUT으로 옮긴다.

> **CI 2종을 M0에 넣은 이유:** 나중에 붙이면 이미 쌓인 코드가 폰에서 안 돌아가는 걸 뒤늦게 발견한다.
> 특히 **터치 조작과 화면 크기는 에뮬레이터로 검증되지 않는다.** 실기에서 처음부터 확인한다.

> **⚠️ 최초 1회 수동 설정:** GitHub 저장소 Settings → Pages → Source를 **GitHub Actions**로
> 바꿔야 웹 배포가 동작한다. 이것만은 코드로 할 수 없다.

### M1에서 내린 결정과 부딪힌 것

| 문제 | 결정 |
|---|---|
| sim이 "화덕"이라는 한글을 알아야 하나 | **아니다.** `data/buildings.json`을 sim과 game이 각각 필요한 키만 읽는다. sim은 숫자, game은 문구. 어긋남은 테스트가 막는다 |
| 건설 중에 다음 건물이 해금되면? | **완공되어야 해금된다.** 착공만으로 열리면 건설 일수가 의미를 잃는다 |
| 자원 표시 순서 | sim의 `tracked_ids()`는 영문 id 알파벳순이라 "석재 · 목재"가 됐다. 표시 순서는 game이 GDD §4.3 분류 순으로 다시 정렬한다 |
| 잠긴 건물을 메뉴에서 숨길까 | **숨기지 않는다.** 무엇이 앞에 있는지 보여야 해금 사슬이 목표로 기능한다 |

**M1의 한계 (의도적):**
- 슬롯 해금 조건이 **연차뿐**이다. GDD §4.5는 인구·명성도 쓴다고 정했지만 둘 다 아직 없다 → M2/M4
- **생산이 없다.** 시작 자원 140/60을 쓰면 그걸로 끝이다. 이게 M2의 존재 이유다
- 건물 화면의 고유 영역이 비어 있다. 골격만 세웠다 → M2

> ⚠️ **M2가 이 게임의 분기점이다.** 지금 상태는 "버튼 누르면 건물이 생기는 화면"이고,
> GDD §4.4가 경고한 방치형 게임과 구별되지 않는다. 건물 화면에 트레이드오프가
> 들어가는 M2를 통과해야 이 기획이 성립한다.

### 정직한 판단 — §4.4는 통과했는가

문서가 "M3으로 넘어가기 전에 정직하게 판단한다"고 했으므로 그대로 적는다.
**부분 통과다.** 건물 화면 넷 중 둘만 날이 서 있다.

| 건물 화면 | 결정의 무게 |
|---|---|
| 나무꾼 오두막 | **강함.** 목재(건설) vs 장작(생존). 밸런스 탐침에서 이걸 잘못 골라 식량 144를 쌓아둔 채 얼어 죽었다 |
| 농장 | **강함.** 순무(지금 먹기) vs 밀(방앗간·화덕에 슬롯과 인력을 걸기). 효율 4.50 vs 6.67 |
| 창고 | **약함.** 배급 정책이 M2에서는 미미하다. 저장 한도가 조여드는 겨울(M3)에야 의미가 생긴다 |
| 오두막 | **없음.** 정보 표시뿐이다 — 사람이 부족한지, 집이 부족한지, 식량이 부족한지 |

"레벨업 버튼만 누르는 화면"은 아니지만, 넷 중 둘이 아직 정보 화면이다.
M3의 겨울 압박이 창고를 살릴 것으로 본다. 오두막은 M4의 병사 유지비가 붙어야 결정이 생긴다.

### 밸런스 탐침이 잡아낸 것 — 단위 테스트 192개가 놓친 두 가지

`tests/balance_probe.gd`는 100일을 자동으로 플레이한다.
"규칙이 맞게 도는가"가 아니라 **"그 규칙으로 만든 게임이 살 만한가"** 를 묻는 도구다.

1. **만성 부족이 아무 결과도 낳지 않았다.**
   `연속으로 며칠 굶었는가`로 세니, 하루 굶고 하루 먹기를 반복하는 마을은
   카운터가 매번 0으로 초기화되어 **필요량의 60%만 먹으면서 영원히 버텼다.**
   → 못 먹은 끼니를 **누적**하고, 배불리 먹은 날에만 조금씩 갚는 모델로 교체.

2. **마을이 성장할 수 없었다.**
   농부 하나가 두 가구를 정확히 break-even으로 먹여서 잉여가 0이었다.
   식량 비축이 늘지 않으니 이주 조건(며칠치)을 영원히 못 넘긴다.
   → 작물 수확량을 올려 농부가 약간의 잉여를 내게 조정.

두 문제 모두 단위 테스트는 전부 초록불인 상태에서 숨어 있었다.

### M2의 한계 (의도적)

- **계절이 생산에 걸리지 않는다.** 겨울에도 농장이 돌고 장작 소비량이 그대로다 → M3
- 농장의 파종 시기·휴경이 없다. 계절이 붙어야 의미가 생긴다 → M3
- 배급 정책에 병사 우선순위가 없다. 병사가 아직 없다 → M4
- 밸런스는 "죽지 않고 굴러간다" 수준이다. 본격적인 조정은 M6

## 세로 화면 전환 (M2 이후)

가로 고정으로 만들었다가 **세로 고정으로 뒤집었다** (GDD D12 수정).
폰을 한 손으로 들고 하는 게임에 가로는 맞지 않는다.

단순한 비율 변경이 아니라 배치를 다시 잡아야 했다:

| 바뀐 것 | 이유 |
|---|---|
| 마을 파노라마가 **세로 스크롤** | 폭 720에 가로 스크롤을 두면 슬롯이 한 번에 3개밖에 안 보인다. 좌우 엇갈림으로 굽이진 마을길처럼 |
| 건물 화면이 **2단 → 세로 스택** | 가로에서는 공통 컨트롤 왼쪽 / 고유 영역 오른쪽이었다. 세로에서는 위→아래, 스크롤로 감싼다 |
| 상단은 정보, 하단은 조작 | 읽기만 하는 것(날짜·자원)은 위, 누르는 것(속도·뒤로)은 아래 — 엄지가 닿는 곳 |
| 속도 버튼이 가로 4등분 전폭 | 하나당 약 170px. 최소 터치 타겟의 두 배 |
| 건설 메뉴에 **건물 설명 한 줄 추가** | 세로에서는 6종이 한 화면에 다 들어와 여백이 남았다. 짓기 전에 무엇을 위한 건물인지 알 수 있게 |
| 하단 여백 56px | 안드로이드 제스처 바. 버튼을 끝까지 붙이면 누를 때 홈으로 나가버린다 |

**여기서 처음으로 도트를 찍는다.** M4까지의 재미가 확인된 뒤에.

- [ ] 마을 파노라마 배경 (계절 4종 — **셰이더 오버레이로 처리, 4장을 그리지 않는다**)
- [ ] 건물 스프라이트 10종 × 상태(미건설/건설중/가동/정지/파손)
- [ ] **건물 화면 UI 10종** ← 작업량의 대부분
- [ ] 전투 유닛 스프라이트 (병사 3종 + 몬스터 3종) + 공격/피격 모션
- [ ] 공용 UI 스킨 (버튼, 슬라이더, 패널, 정보 바)

**완료 기준:** 스크린샷을 찍어서 남에게 보여줄 수 있다.

> **⚠️ 이 단계가 프로젝트를 죽일 수 있다.**
> 타일맵이었다면 타일셋 한 벌로 끝났을 것이 화면 10개가 됐다.
> **아웃소싱 또는 에셋 구매를 진지하게 검토할 지점.**
> 직접 찍겠다면 건물 수를 6~8종으로 줄이는 것을 먼저 고려한다.

## M6 — 무역과 원정 (2~3주)

경제 고리를 닫는 단계. **여기서 게임이 완성된 형태가 된다.**

- [ ] 몬스터 부산물 (마정석 · 가죽 · 뿔) 드랍
- [ ] 교역소 화면 — 시세, 교역대 편성, 호위 배정, 목적지
- [ ] 은화 도입 + **병사 임금** (미지급 시 사기 하락/이탈)
- [ ] 겨울 교역로 폐쇄
- [ ] 교역대 호위 전투 (BattleSim 재사용)
- [ ] 영주관 화면 — **토벌 원정 파견**, 마을 방어 공백 발생
- [ ] 소굴 제거 시 해당 방향 습격 빈도 감소

**완료 기준:** GDD §1.3의 핵심 순환이 실제로 돌아간다.
몬스터를 잡아야 돈이 생기고, 돈이 없으면 병사가 떠난다.

- [ ] 장비 지급 UI

**완료 기준:** 마정석 앞에서 매번 갈등하게 된다.

## 중단 지점 (Kill Points)

프로젝트를 정직하게 관리하기 위한 사전 합의. **여기서 재미없으면 방향을 바꾼다.**

| 시점 | 확인할 것 | 실패 시 |
|---|---|---|
| **M2 종료** ⭐ | **건물 화면에서 하는 결정이 고민되는가?** 슬라이더만 밀고 있지 않은가? | §4.4의 대체 깊이가 부족한 것. 건물 화면에 미니 시스템을 더 넣거나, 타일맵 복귀를 재검토 |
| **M3 종료** ⭐ | 첫 겨울을 넘기는 것이 긴장되는가? | **가장 중요한 검증 지점.** 여기서 재미없으면 기획 자체를 재검토 |
| **M4 종료** | 자동 전투 관전이 지루하지 않은가? | 명령 포인트 재설계 |
| **M5 중간** | 건물 화면 10개를 그릴 체력이 있는가? | 건물 수 축소 또는 아웃소싱/에셋 구매 |
| **M6 종료** | 핵심 순환이 플레이어를 밖으로 밀어내는가? | 무역 보상 또는 임금 압박 강도 조정 |

**M2와 M3이 가장 중요하다.**
M2는 이번 설계 변경(D13)이 옳았는지를 검증하고, M3은 아트에 손대기 전 재미를 검증하는 마지막 지점이다.
